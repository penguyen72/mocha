# Save the Date Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `apps/save-the-date`, a third independently deployed Next.js application, by porting
the `Save the Date.dc.html` Claude Design prototype into this monorepo's existing architecture.

**Architecture:** Two routes — `/` carries a three-phase client state machine
(`closed → opening → open`) for the envelope, and `/share-your-address` is a real App Router route
holding the address form. The invitation is drawn in a fixed 455 × 779 design space scaled by a
container query, so the entire opening choreography is static CSS keyframes with no JavaScript
measurement and no animation library in the app.

**Tech Stack:** Next.js 16.3.1 (App Router), React 19.2.8, Tailwind CSS v4, `@mocha/ui`,
react-hook-form + Zod, Vitest 4 + React Testing Library, pnpm + Turborepo.

- **Source of truth for copy and geometry:** `docs/superpowers/reference/save-the-date-dc-source.md`.
  Section copy must be **verbatim** from it, never paraphrased.

- **Do not run `create-next-app`.** Every config file is written by hand from `apps/blackberry`.
- **pnpm only.** No npm or Yarn lockfiles.
- **Do not touch** `apps/canton` or `apps/blackberry` content.
- **Do not add anything to `packages/ui`.** Reuse only what `packages/ui/src/index.ts` exports.
- **Pinned versions:** `next` `16.3.1`, `react` and `react-dom` `19.2.8`, `@mocha/ui` `workspace:*`.
  All other dependency ranges are copied verbatim from `apps/blackberry/package.json`.
- **Server Components by default.** Only `invitation-stage.tsx` and `address-form.tsx` carry
  `"use client"`.
- **Named exports only**, except the default exports in `app/page.tsx`, `app/layout.tsx` and
  `app/share-your-address/page.tsx`.
- **No user-visible string literal is ever inlined in JSX.** All copy lives in
  `*-content.ts` as `SCREAMING_SNAKE_CASE` consts, with exported `type`s for repeated item shapes,
  and multi-line strings written as explicit `" … " +` concatenation.
- **No raw hex value anywhere in `src/`, outside `src/app/globals.css`.**
- **Tailwind v4 utility classes only.** No CSS modules, no styled-components, no inline `style`
  objects, no `<style>` tags. Multi-part decorative values are named `--std-*` custom properties in
  `globals.css`, referenced from JSX as single-token arbitrary properties.
- **Tailwind class names must be literal strings.** Never build a class with a template literal —
  Tailwind scans source text and would not generate it.
- **Import ordering**, blank-line separated groups: (1) external packages, (2) `@mocha/ui`,
  (3) `@/components/*`, (4) relative `./*-content` imports, (5) `@/assets/*` last.
- **Mobile-first.** Base classes target phones; `sm:` / `lg:` layer up. Never allow horizontal
  scroll.
- **Accessibility:** decorative glyphs get `aria-hidden`; every control is at least 44 × 44px;
  every focusable element shows a visible focus outline.
- **Tests assert against the imported content consts**, never against duplicated literals, and query

  - Animation shorthands, all referenced as `[animation:var(--std-anim-…)]`:
    `--std-anim-stage-in`, `--std-anim-prompt-out`, `--std-anim-seal-out`, `--std-anim-flap`,

    `--std-anim-ribbon-z`, `--std-anim-note-in`, `--std-anim-petal-0` … `--std-anim-petal-6`.

**Why plain `:root` custom properties rather than `@theme inline { --animate-* }`:** three elements
(the flap and each card) need **two** simultaneous animations — a transform and a discrete
`z-index` step. Tailwind's `animate-*` utility writes the whole `animation` shorthand, so two of
them on one element would conflict. Composing with one arbitrary property,
`[animation:var(--std-anim-card-a),var(--std-anim-card-a-z)]`, is the only way to run both, and it
requires the shorthands to be real custom properties. Keeping **all** of them in `:root` for
consistency also makes the `prefers-reduced-motion` override a single block that switches every
animation off at once.

**Interfaces:**
- Consumes: Task 2's tokens.
- Produces:
  - `type InvitationPhase = "closed" | "opening" | "open"` and `OPENING_DURATION_MS: number`.
  - `FloralSprig({ className }: { className: string })` — one 22 × 22 design-unit sprig. The
    caller supplies **all** positioning, sizing and rotation as a literal class string.
  - `PetalScatter({ animated }: { animated: boolean })` — the seven petals, absolutely positioned
    across `inset-0` of the stage frame.
  - Every invitation string, listed in Step 1.

**A Tailwind rule that governs this task and the next four.** Tailwind v4 scans source *text* for
class names, so a class name must appear as a literal in the file. Two consequences:

1. Never build a class name from a value — `` `left-[${x}%]` `` is never generated. Repeated
   geometry is stored as an **array of complete literal class strings**.
2. Joining two complete literal strings is fine — `` `${BASE[i]} ${ANIM[i]}` `` works, because both
   halves appear literally in the source and Tailwind finds them there.

**A transform rule that governs this task and the next four.** Use the arbitrary property
`[transform:rotate(-9deg)]`, never Tailwind's `rotate-[-9deg]`. In Tailwind v4 `rotate-*` writes the
independent `rotate` property, which composes *on top of* `transform` — so an element whose keyframes
animate `transform` would end up rotated twice.

must match it. A visitor arriving at `/#open` is upgraded in an effect. The stage's unconditional

```tsx
"use client";

import { useCallback, useEffect, useRef, useState } from "react";

import { AnnouncementCard } from "./announcement-card";
import { DateCard } from "./date-card";
import { Envelope } from "./envelope";
import { InvitationNote } from "./invitation-note";
import { PetalScatter } from "./petal-scatter";
import { PhotoCard } from "./photo-card";
import { Ribbon } from "./ribbon";

import { INVITATION_HEADING } from "./invitation-content";
import { OPENING_DURATION_MS, type InvitationPhase } from "./invitation-phase";

/** Addressable state for the opened invitation, so "back to invitation" can return to it. */
const OPEN_HASH = "#open";

const STAGE_FRAME =
  "relative aspect-[455/779] w-[min(100vw,560px,max(58.4dvh,340px))] flex-none " +
  "[animation:var(--std-anim-stage-in)] @container";

function prefersReducedMotion() {
  return (
    typeof window.matchMedia === "function" &&
    window.matchMedia("(prefers-reduced-motion: reduce)").matches
  );
}

export function InvitationStage() {
  const [phase, setPhase] = useState<InvitationPhase>("closed");
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);
  const headingRef = useRef<HTMLHeadingElement>(null);
  const previousPhaseRef = useRef<InvitationPhase>("closed");

  // The server prerenders the closed envelope, so the first client render must match it.
  // Arriving at /#open upgrades here; the stage's 300ms fade-in covers the swap.
  useEffect(() => {
    if (window.location.hash === OPEN_HASH) {
      setPhase("open");
    }
  }, []);

  useEffect(
    () => () => {
      if (timerRef.current !== null) {
        clearTimeout(timerRef.current);
      }
    },
    [],
  );

  // Announce the invitation once it has finished opening.
  useEffect(() => {
    if (previousPhaseRef.current === "opening" && phase === "open") {
      headingRef.current?.focus({ preventScroll: true });
    }
    previousPhaseRef.current = phase;
  }, [phase]);

  const open = useCallback(() => {
    if (phase !== "closed") return;

    window.history.replaceState(null, "", OPEN_HASH);

    if (prefersReducedMotion()) {
      setPhase("open");
      return;
    }

    setPhase("opening");
    timerRef.current = setTimeout(() => setPhase("open"), OPENING_DURATION_MS);
  }, [phase]);

  const opening = phase === "opening";
  const revealed = phase !== "closed";

  return (
    <div className={STAGE_FRAME}>
      <Envelope phase={phase} onOpen={open} />

      {revealed && (
        <>
          <h1 ref={headingRef} tabIndex={-1} className="sr-only">
            {INVITATION_HEADING}
          </h1>
          <PetalScatter animated={opening} />
          {opening && <Ribbon />}
          <AnnouncementCard animated={opening} />
          <DateCard animated={opening} />
          <PhotoCard animated={opening} />
          <InvitationNote animated={opening} />
        </>
      )}
    </div>
  );
}
```

| --- | --- |

## How it is built

The invitation is drawn in a fixed 455 × 779 design space and scaled by a container query on the
stage frame, so `--std-u` (`0.2198cqw`) is one design pixel. That makes every value in the opening
choreography a static number, so the whole sequence is CSS `@keyframes` in `src/app/globals.css`
rather than JavaScript — no measurement, no resize listener, no animation library in this app.

`src/components/invitation-stage.tsx` and `src/components/address-form.tsx` are the only client
components. `--std-*` is this app's local palette and is **not** part of the shared `@mocha/ui`
token contract.

The design this was ported from is recorded in
[`docs/superpowers/reference/save-the-date-dc-source.md`](../../docs/superpowers/reference/save-the-date-dc-source.md),
with the approved design in
[`docs/superpowers/specs/2026-09-23-save-the-date-design.md`](../../docs/superpowers/specs/2026-09-23-save-the-date-design.md).

## Known gaps

- **Three images are placeholders.** The floral background, the couple photograph and the wax seal
  live in Canva and were never exported into the design project. Each renders as a CSS gradient
  built from app-local tokens. The photograph's intended alt text is preserved in
  `src/components/invitation-content.ts` as `PHOTO_ALT`, ready for the real file.
- **The champagne-glass illustration is missing.** The design prototype drew a dashed placeholder
  box on the date card to mark it. That box is deliberately not ported — in production it would read
  as a rendering bug — so the date card is slightly barer than the design until the export arrives.
- **The address form does not submit anywhere.** `src/components/address-submit.ts` is the single
  seam: it validates and resolves after a short delay, and the form's error state is driven by that
  promise rejecting. Wiring a real endpoint or form provider there makes the whole status machine
  live. Nothing is stored or sent today.
- **Opening the envelope needs JavaScript.** The prerendered HTML is the sealed envelope, so a
  visitor with JavaScript disabled sees the envelope but cannot open it.
