# Turborepo Wedding Sites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a pnpm/Turborepo boilerplate containing independently deployable Canton and Blackberry Next.js applications with shared UI and tooling packages.

**Architecture:** A custom Turborepo root owns orchestration and workspace installation. The official `create-next-app` CLI generates each Next.js application, after which both apps consume source-based `@mocha/ui`, `@mocha/eslint-config`, and `@mocha/typescript-config` workspaces. Vercel deploys the apps as separate projects rooted at their respective app directories.

**Tech Stack:** Node.js 24.x, pnpm 10.15.0, Turborepo 2, Next.js 16.2, React 19, TypeScript 5, Tailwind CSS 4, ESLint 9, Vitest, React Testing Library, GitHub Actions, Vercel

**Spec:** `docs/superpowers/specs/2026-08-18-turborepo-wedding-sites-design.md`

## Global Constraints

- Generate `apps/canton` and `apps/blackberry` with recorded `npx create-next-app@latest` commands; do not hand-create their initial framework scaffolds.
- Use pnpm workspaces and pin `packageManager` to `pnpm@10.15.0`.
- Use Node.js `24.x` locally, in package metadata, in CI, and on Vercel.
- Use TypeScript, ESLint, Tailwind CSS, App Router, a `src/` directory, the `@/*` alias, and Turbopack in both apps.
- Canton runs locally on port 3000; Blackberry runs locally on port 3001.
- Default to Server Components and add `"use client"` only for browser-dependent behavior.
- Keep wedding-specific copy and composition inside each application.
- Put only genuinely shared design tokens and visual primitives in `@mocha/ui`.
- Do not install shadcn/ui, Playwright, a database, authentication, storage, analytics, a CMS, or form services.
- Preserve any app-local `AGENTS.md` files produced by `create-next-app`.
- Use only the minimal placeholder copy approved by the spec.
- All of `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm build` must pass before completion.

## File Responsibility Map

### Root orchestration

- `package.json`: repository identity, Node/pnpm constraints, and Turbo entry-point scripts.
- `pnpm-workspace.yaml`: discovers `apps/*` and `packages/*`.
- `turbo.json`: task dependencies, persistence, and cache outputs.
- `.gitignore`: root dependency, cache, coverage, build, and environment exclusions.
- `.node-version`: local Node.js major selection.
- `pnpm-lock.yaml`: exact dependency graph generated by pnpm.

### Applications

- `apps/canton/package.json`: Canton dependencies, scripts, and port 3000.
- `apps/blackberry/package.json`: Blackberry dependencies, scripts, and port 3001.
- `apps/*/next.config.ts`: transpiles the source-based shared UI package.
- `apps/*/tsconfig.json`: extends the shared Next.js TypeScript preset.
- `apps/*/eslint.config.mjs`: imports the shared Next.js ESLint preset.
- `apps/*/src/app/layout.tsx`: app-specific document metadata and root layout.
- `apps/*/src/app/page.tsx`: app-specific placeholder composed with `SiteShell`.
- `apps/*/src/app/globals.css`: Tailwind entry point, shared theme import, and external UI source registration.

### Shared packages

- `packages/typescript-config/base.json`: strict, bundler-oriented TypeScript defaults.
- `packages/typescript-config/nextjs.json`: Next.js compiler additions.
- `packages/typescript-config/react-library.json`: React library compiler additions.
- `packages/eslint-config/next.mjs`: Next.js core-web-vitals and TypeScript flat config.
- `packages/eslint-config/react.mjs`: TypeScript and React Hooks flat config for the UI library.
- `packages/ui/src/site-shell.tsx`: server-compatible shared placeholder shell.
- `packages/ui/src/styles.css`: common CSS tokens exposed to both applications.
- `packages/ui/src/index.ts`: public UI exports.
- `packages/ui/src/site-shell.test.tsx`: behavioral smoke test.
- `packages/ui/vitest.config.ts`: jsdom and React test transformation.
- `packages/ui/vitest.setup.ts`: Testing Library DOM matchers.

### Contributor operations

- `.github/workflows/ci.yml`: frozen install and four required verification commands.
- `README.md`: human setup, architecture, commands, deployment, and Superpowers workflow.
- `AGENTS.md`: direct repository rules for compatible coding agents.
